# AdCoin: точная Smali-цепочка MAX reward callback

Источник: `apk_analysis/apktool/smali/v9.smali`, `p70.smali`, `s00.smali`; сопоставление с JADX `p70.java`.

## 1. Подтверждённая цепочка после `onUserRewarded`

В `defpackage/p70.java` метод:

```java
onUserRewarded(MaxAd maxAd, MaxReward maxReward)
```

проверяет оба аргумента на null и запускает coroutine:

```java
ep2.E(this.d, null, null, new v9((byte) 1, null, this), 3);
```

В `v9.smali` discriminator `1` соответствует `:pswitch_1b`. Ветка:

1. Берёт `p70.b` (`av2`).
2. Берёт `av2.b` — поток/источник значения типа `ai1`.
3. Получает из него `String` через `ljdb.y(...)`.
4. Если строка не null, вызывает `s00.e0(String)`.
5. Записывает полученный `Integer` в глобальное состояние `g70.H` (`Lj8a`).
6. Исключения в этой ветке перехватываются; наружу не пробрасываются.

Важное наблюдение: в этой app-side ветке `MaxReward maxReward` не читается. Callback служит триггером последующего запроса, но размер награды из `MaxReward` в запрос явно не передаётся.

## 2. Что делает `s00.e0`

Smali `s00.e0(String, ...)` строит путь:

```text
forGooglePlayVersion/refBonus/get/{value}
```

Затем создаёт пустой `p95` request, формирует запрос с verb `z85.b` (GET) и отправляет его через общий сетевой клиент `x65`.

Успешный ответ десериализуется как `Integer`.

Итого подтверждено:

```http
GET /forGooglePlayVersion/refBonus/get/{value}
```

- host задаётся общей конфигурацией API AdCoin (`api.adcoinapp.com`);
- query/body в этом методе не добавляются;
- ответ — целое число;
- число сохраняется в `g70.H`.

## 3. Что это означает — и чего не означает

Название маршрута `refBonus` указывает на referral bonus. В сочетании с тем, что метод возвращает integer и сохраняет его в отдельное глобальное состояние, это больше похоже на обновление значения/счётчика реферального бонуса, чем на передачу факта просмотра рекламы для начисления монет.

Это интерпретация имени маршрута и структуры вызова, а не доказательство серверной бизнес-логики. В исходниках не найдено подтверждения, что `/forGooglePlayVersion/refBonus/get/{value}` зачисляет вознаграждение за рекламу.

Также нельзя утверждать, что запрос сообщает серверу об успешном просмотре: в нём нет явного `MaxAd`, `MaxReward`, ad unit id или placement. Единственный динамический параметр — строка из `av2.b`.

## 4. Новое уточнение относительно предыдущих выводов

`p70.onUserRewarded -> v9(discriminator=1)` теперь восстановлен на Smali-уровне. Это не неизвестная корутина: она делает GET `forGooglePlayVersion/refBonus/get/{value}` и обновляет `g70.H`.

Следовательно, это **не найденный endpoint начисления рекламных монет**. Предыдущая гипотеза о возможной связи callback с balance refresh должна быть ограничена: эта ветка обновляет `g70.H`, а не вызывает `s00.R0()` и не обновляет `ir4.balance` напрямую.

## 5. Следующие точки анализа

- Установить источник и смысл строки `av2.b` (какой именно ID/ключ передаётся в `refBonus/get`).
- Проследить, где UI использует `g70.H` и как поле `ja.n` инициализирует его.
- Проверить другие rewarded-ad реализации (Google AdMob/GAM и BidMachine) и их app-side callbacks: в APK есть дополнительные rewarded адаптеры.
- Продолжить поиск собственного AdCoin endpoint, который меняет balance/task progress. В текущих найденных методах `s00.e0` таким endpoint не является.

## 6. Безопасные границы

Отчёт фиксирует статическую структуру клиента. Он не содержит реальных пользовательских токенов, рекламных идентификаторов или инструкций по подделке reward callback. Не следует самостоятельно отправлять повторные reward-запросы или имитировать SDK callback.
