# AdCoin reward / balance flow — уточнение по Smali (2026-11-26)

## 1. Исправление предыдущей интерпретации `v9`

`v9` — общий synthetic coroutine с discriminator-switch, а не одна корутина. В `invokeSuspend()` значение `r=1` попадает в `:pswitch_1b`. Эта ветка явно делает `check-cast v13, Lp70;` и выполняет:

1. читает строку через `p70.b -> lav2.b -> ai1`;
2. вызывает `s00.e0(String)`;
3. получает `Number`, преобразует в `int`;
4. записывает число в `g70.H`.

Это подтверждает вызов `refBonus/get` из `p70.onUserRewarded()`, но не подтверждает зачисление награды за просмотр рекламы. `MaxReward` в `p70.onUserRewarded()` проверяется на null через `getClass()`, но его reward amount не читается и в запрос не передаётся.

Smali:
- `p70.smali`, метод `onUserRewarded`, строки около 1030–1071.
- `v9.smali`, `invokeSuspend`, ветка `:pswitch_1b`, около 2088–2168.
- `s00.smali`, метод `e0`, путь `forGooglePlayVersion/refBonus/get/`.

## 2. Отдельная ветка `withdrawal/methods/get`

В `s00.smali` метод `R0(String)` формирует URL `withdrawal/methods/get/{value}`, выполняет HTTP-запрос через `xhc` и десериализует ответ.

В `v9.smali` helper `m(Object)` (не ветка discriminator 1) вызывает `s00.R0`, читает из `ir4`:
- `ir4.b` — `double`;
- `ir4.a` — список методов вывода;
и сохраняет `ir4.b` в `g70.D`.

Следовательно, `g70.D` — значение баланса, полученное вместе со списком withdrawal methods. Не следует приписывать этот запрос callback `p70.onUserRewarded()`.

## 3. Отдельный запрос `adcoin/updateData` тоже возвращает balance

В `xn3.smali`, метод `l()`, используется `Lebb;->a(...)`. `ebb.smali` создаёт DTO `abb` и вызывает `s00.H1(abb)`.

В `s00.smali`, метод `H1`, явно формируется:

```http
POST adcoin/updateData
```

Тело сериализуется как `abb`, у которого четыре строковых поля `a`, `b`, `c`, `d`. По ранее установленной модели это access token, device ID, advertising ID и messaging token; точное соответствие аргументов в конкретном callsite надо сохранять отдельно от общей модели.

Ответ в `xn3.l()` десериализуется как `dbb`. После успешного ответа приложение:
- передаёт `dbb.c` в `g70.p(int)`;
- записывает `dbb.a` (`double`) в `g70.D`;
- передаёт `dbb.b` в `g70.r(int)`.

Это важное подтверждение: `adcoin/updateData` возвращает значение, которое приложение использует как balance (`g70.D`). Однако в изученном callsite нет доказательства, что этот POST сам создаёт рекламное начисление. Это синхронизация/обновление пользовательских данных и состояния кошелька.

Smali:
- `ebb.smali`, метод `a`.
- `abb.smali`, поля `a`–`d`.
- `s00.smali`, метод `H1`, строка `adcoin/updateData`.
- `xn3.smali`, метод `l`, разбор `dbb` и запись в `g70.D`.
- `dbb.smali`, поле `a` — double; `b` и `c` — int.

## 4. Что теперь подтверждено

| Событие / запрос | Результат |
|---|---|
| AppLovin `onUserRewarded` | вызывает `refBonus/get`; amount из `MaxReward` не используется |
| `withdrawal/methods/get/{value}` | возвращает `ir4`; `ir4.b` записывается в balance state `g70.D` |
| `POST adcoin/updateData` | возвращает `dbb`; `dbb.a` записывается в `g70.D` |
| Реальное серверное начисление reward за рекламу | в этих цепочках не доказано |

## 5. Следующее направление

Дальше необходимо сопоставить `xn3.l()` с конкретным UI/event caller, затем проверить все места вызова `adcoin/updateData` и все сетевые операции, которые возвращают `dbb` или меняют `g70.D`. Это позволит выяснить, `updateData` лишь перечитывает баланс или запускает серверную обработку событий рекламных партнёров. Сам endpoint и DTO недостаточны, чтобы заявлять о механизме начисления.

## 6. Проверка HTTP verbs

В `z85.smali` enum-like class явно сопоставляет:
- `z85.b` = `GET`;
- `z85.c` = `POST`.

Поэтому методы подтверждены так:
- `s00.e0()` (`refBonus/get`) — GET;
- `s00.R0()` (`withdrawal/methods/get`) — GET;
- `s00.H1()` (`adcoin/updateData`) — POST.

## 7. Контекст вызова `adcoin/updateData`

В `xn3.l()` перед созданием запроса приложение получает текущую строку `g70.i()` и несколько строковых значений из `od5` (через `od5.b()`, `od5.a()` и `od5.b:ew8`). Затем они передаются в `ebb.a(...)`, преобразуются в DTO `abb` и отправляются через `s00.H1()`.

Успешный ответ `dbb` обновляет несколько глобальных состояний приложения, включая `g70.D`. Это подтверждает, что updateData является источником актуального баланса для данного потока. При этом в теле `abb` нет явного `reward`, `amount`, `adUnitId` или `transactionId`; из одного этого запроса нельзя заключить, что он непосредственно зачисляет конкретную рекламную награду.

## 8. Дополнительные собственные AdCoin endpoints, найденные в `s00.smali`

При полном просмотре строк маршрутов `s00` обнаружены также:

| Метод | HTTP | Назначение по имени маршрута |
|---|---|---|
| `adcoin/getUserData` | POST | получение пользовательских данных; ответ `gk4` |
| `adcoin/updateData` | POST | обновление пользовательских данных; ответ `dbb`, содержит `double` и целочисленные статусы |
| `adcoin/promoCode/apply` | POST | применение промокода; ответ `a90` |
| `adcoin/partners/get/{value}` | GET | список партнёров |
| `adcoin/refStats/get/{value}` | GET | реферальная статистика |
| `adcoin/refStats/fullStats/get/{value}` | GET | расширенная реферальная статистика |
| `adcoin/season/quests/get/{value}` | GET | сезонные задания |
| `adcoin/season/get/{value}` | GET | сезонные данные |
| `adcoin/trophy/get/{value}` | GET | данные трофеев |

Также присутствуют `withdrawal/make`, `withdrawal/repeat`, `withdrawal/ownHistory/get` — это операции вывода средств, а не рекламного начисления.

В строковых маршрутах `s00.smali`, которые были перечислены, отдельного очевидного `adcoin/reward/*` или `adcoin/ads/*` endpoint не обнаружено. Это не доказывает полного отсутствия динамически собираемого маршрута или серверного postback: только фиксирует результат статического поиска строк в данном API-клиенте.
